# Retained RESOLVE Required-Quantity Reconciliation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reconcile explicitly selected archived RESOLVE producers into reproducible required-quantity decisions and optional governed state, with validated source-free recovery.

**Architecture:** A distinct synchronous recorded-producer operation admits a complete fixed-topology plan but constructs and invokes only RECONCILE. Procurement owns the authority bridge, existing policy and independent postconditions; neutral immutable records preserve historical producers separately from the actual current operation. An additive Postgres capability retains exact producer joins and result atomically through a neutral port and explicit bootstrap composition.

**Tech Stack:** Python stdlib frozen dataclasses/Protocols/argparse/JSON/Decimal, existing SemanticCodec and physical planner, optional psycopg/Postgres16, pytest; no new dependency, model or scorer.

**Spec:** [Owner-approved design](../specs/2026-10-24-retained-resolve-reconciliation-design.md), exact approval `2c1b759768cfd577c3d9e4a589b655d390b46c9f` on 2026-10-24; [ADR047](../../adr/047-retained-resolution-required-quantity-reconciliation.md), decision [#238](https://github.com/stauntonjr/procurement-intelligence-lab/issues/238). Implementation [#239](https://github.com/stauntonjr/procurement-intelligence-lab/issues/239), primary M4, native parent #20. Baseline main `a8de65db7ae6b6192a937ae930859d1b205be5aa`.

**Plan status:** Written for owner review; product implementation has not started. Preserve Native/inline execution and one independent final architecture/semantic review. Design approval is recorded; it does not establish implementation acceptance or review of this plan.

## Global Constraints

- Core owns semantics; adapters own mechanics. Neutral runtime/ports import no procurement, storage driver or framework. Bootstrap owns explicit composition; use stdlib dataclasses and Protocols.
- Profile `retained-resolution-reconciliation/v1`; storage capability `retained_resolution_reconciliation/v1`; new source profile `retained-resolved-required-quantity` version `1.0.0`; RECONCILE declaration `procurement.reconcile/governed-required-quantity@1` uses unchanged `procurement-governing-claims/v1`.
- One to eight explicitly selected already-retained six-stage producers, exact four-part source scope including version, same complete candidate semantic snapshot and supported `procurement_item`/`internal_sku` resolution policy. No ambient latest selection, capture, import or upstream executor construction.
- RECONCILE executes exactly once per admitted call. Twelve current dispositions: RECONCILE SUCCEEDED, eleven NOT_EXECUTED. Historical producer receipts are separate. Requested-operation completion true only after validation; package execution completion always false.
- Preserve original bom-table manifest/defaults, source-precedence behavior, all five/six-stage constructors, codecs, digests, public callers and jobs. No seven-stage prefix or durable reconciliation job; DERIVE through ACT remain uninvoked.
- Reject duplicate execution/artifact/content/revision membership, repeated item quantity rows, unknown/missing/negative quantity, unsupported quantity unit and unresolved identity before invoke. Selected supersession pairs require identical resolved item sets. No aggregation, implicit conversion, deletion or fabricated zero.
- Metadata is at most64KiB strict UTF-8 JSON; retain raw audit bytes separately from canonical semantic identity. It is a trusted local synthetic attestation, not enterprise approval verification, signature, model authority or human confirmation.
- Approval/effectivity/explicit supersession follow existing policy v1. As-of <= operation started_at; producer capture <= operation started_at. As-of may precede ingestion. Preserve fixed timezone offsets in identities; aware instant comparisons determine eligibility.
- Governed state: required_quantity, each, EpistemicStatus.OBSERVED, separate ProcurementStateBasis.RECONCILED audit, exact ADR024 scope identity and UNKNOWN freshness. Unresolved projects no state; zero is valid. No observed procurement, outstanding, price, delivery or human-confirmed state.
- Existing per-record codec bounds stay16MiB/50,000 nodes/depth64. New aggregate selected-producer budget is4MiB and12,500 decoded graph nodes, defined below. No secrets/DSNs/settings dumps/tracebacks in results or evidence.
- CLI needs optional storage even without result append. Explicit initialization only; immutable joins, atomic first retention and uncertain acknowledgement semantics. History default100/max200, nonnegative cursor; atomic no-overwrite export.
- Use synthetic data and preserve unrelated services/files. No dependency/provider/model/algorithm replacement, deployment, listener/worker work, operational-agent authority or broader M4 completion.

### Authority and policy JSON

Freeze authority root exactly `{"schema_version":"1.0","producers":[...]}`. One to eight records, exactly one per selected execution digest. Every record has exactly these required keys:

| Key | Wire type and bound |
|---|---|
| execution_digest | lowercase64 hexadecimal SHA256 |
| artifact_id | nonblank string, maximum1024 Unicode code points; exact recorded artifact identity |
| content_hash | lowercase64 hexadecimal SHA256; exact recorded content hash |
| revision_id | nonblank string, maximum256 code points; unique across selected records |
| supersedes_revision_ids | array of0–8 unique nonblank strings, maximum256 code points each; no self-reference |
| source_role | exact existing GoverningSourceType value: approved_bom_revision, approved_purchase_order_line, accepted_supplier_quote, supplier_confirmed_commitment, receipt or inspection; policy v1 alone decides required-quantity eligibility |
| approval | null, or exactly `{"record_ref":string,"approved_at":aware ISO8601 string}`; record_ref nonblank/max1024 |
| effective_from | required aware ISO8601 string |
| effective_until | null or aware ISO8601 string, strictly after effective_from |
| document_at | required aware ISO8601 string |

All mandatory fields remain mandatory when null/empty is permitted. Reject unknown/duplicate keys, booleans where other types are required, nonfinite constants, invalid UTF-8, lone surrogates and recursion deeper than16 before storage. Time strings max128 code points; all IDs retain exact text, reject surrounding whitespace/control characters rather than trim. Canonical metadata sorts records by execution_digest and supersession IDs lexically, sorts object keys and uses compact ensure_ascii JSON; it preserves ISO offsets via datetime.isoformat(), without converting instants to UTC. Null approval maps to approved_at=None; source role alone never grants approval. Scope and ingested_at derive exclusively from producers.

Policy JSON is at most32KiB, exact keys `profile`, `policy_id`, `predicate`, `quantity_unit`, all strings and exactly `retained-resolution-reconciliation/v1`, `procurement-governing-claims/v1`, `required_quantity`, `each`. `ReconciliationPolicyEvidence.reference` uses the plan's declared policy reference; content_digest is existing execution.identity.digest(dict(sorted(parameters))) over those four fields. No policy document/network lookup or alternate version fallback. The exact declaration_ref is `procurement.reconcile/governed-required-quantity@1`, reference_id is `procurement-governing-claims/v1`; all raw/canonical bindings are checked before execution and on recovery.

### Bounds, ordering and identity

For each selected retained producer, validate existing16MiB/50,000/depth64 codec bounds. Aggregate **sum** of its encoded allowlist graph UTF-8 length plus original source byte_length across all producers must be <=4*1024*1024; sum of decoded graph node counts must be <=12,500. Count every selected producer, even shared graph nodes, and check each running total before loading the next producer or invoking. This is an admission budget, not a storage-format change; oversized input fails unsupported-input with known producer recovery IDs. A result/export still must satisfy existing16MiB/50,000/depth64 bounds; output exceeding them is an invoked-output contract failure with no append, never a successful truncated result.

Producer order is ascending execution_digest; claim order is ascending canonicalized_assertion_id; domain candidate order is claim_id (existing policy); item order is canonical_key. Evidence is unique in first governing-candidate order. Numeric values remain exact Decimal; do not turn equality into float/tolerance comparison. No sort key becomes authority.

New computation namespace `retained-resolution-reconciliation-v1` binds full plan, operation context, exact aware as-of, semantic policy/authority, producer computation payloads and full admitted semantic content using existing same_resolved_computation semantics, and actual output/entries. Producer raw catalog formatting, producer completion/archive receipts, current completion and raw authority formatting are audit-only. Include source semantic content/snapshot binding as well as execution digests; compare full values on same-digest retry. Operation context config_digest is derived from canonical manifest/registry/config/policy/authority, not file formatting. Use an explicit output projection (decisions, states, outside_predicate_ids, canonical domain_audit, current provenance and entries), never canonical(output) with raw input evidence still embedded. Current receipt identity retains all raw/audit values. IDs never depend on their own event/receipt IDs.

| ReconciledOutput | inputs:RetainedReconciliationInputs, decisions:tuple[ReconciliationDecision,...], states:tuple[OperationalState,...], outside_predicate_ids:tuple[str,...], domain_audit:bytes, provenance:DecisionProvenance; domain_audit canonical JSON <=4MiB; batch_id/reference_ids/event derived, with batch_id even for empty output |

`ReconciledOutput.event` is an actual `required-quantity-reconciliation` TransformationEvent. Inputs link all recorded producer sixth events and authority/policy IDs; parent_event_ids are those historical sixth events. Outputs include batch_id, neutral decision IDs, state IDs and audit digest, so genuinely empty input still emits an event. Neutral checks require disjoint/exhaustive quantity decision membership and outside_predicate_ids over original source assertion IDs, exact current provenance and exact decision/state links; domain verifies quantity meaning and projection. No original source assertion is rewritten.

Boundary failures: admission uses existing PackageExecutionError; add `UnsupportedReconciliationInputError` (input category/code `pil.input.reconciliation_input_unsupported`) for valid six-stage evidence outside this profile. Invoked output uses PackageExecutionContractError; storage uses existing ArchiveUnavailable/NotFound/Conflict/Integrity families. Recovery translates stored invalid/unsupported evidence to integrity rather than not-found or admission. Public errors add only known scope plus selected producer digests and their existing recovery commands, not raw input/settings/secrets.
